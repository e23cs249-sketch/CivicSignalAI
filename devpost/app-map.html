How a report moves through the app

A local civic-reporting prototype connects a resident's report to a staff response and a shared status history. It is not connected to a city service.

Reference route through the source

  1. static/report.html defines the three-step form; static/js/app.js handles map selection, preview, report submission, and photo upload.
  2. app/api/reports.py provides citizen-protected report and media endpoints. app/database.py persists report ownership, timeline events, and media metadata.
  3. app/api/team.py applies staff-authenticated workflow updates; static/js/tracking.js and static/js/team-dashboard.js show the resulting status and timeline.

Identity, authorization, and private media

Sessions and report ownership

app/api/auth.py handles citizen and staff login, scrypt password hashes, hashed session tokens, and HTTP-only SameSite cookies. Report APIs scope resident access to the authenticated owner; staff routes require a staff session.

Staff accounts are provisioned interactively by app/provision_team_user.py. Startup does not create a demo account.

Photo evidence

app/services/media.py verifies and re-encodes JPG, PNG, or WebP uploads. Files are kept outside static/; the media endpoint returns them only to the report owner or signed-in staff.

Storage defaults to data/private-uploads/. Do not copy local images or databases into a public repository or recording.

To change this, start here

  • Form fields and map interaction: static/report.html and static/js/app.js.
  • Validation and stored report fields: app/schemas.py, app/api/reports.py, and app/database.py.
  • Allowed status transitions: app/services/workflow.py and app/api/team.py.
  • Photo type, size, processing, and storage: app/services/media.py.

A practice to reuse

Keep preview separate from final submission, then test the side effect: preview_report reads candidates and returns suggestions, while create_report stores the report and first event together. Tests in tests/test_api_reports.py and tests/test_persistence.py check API and persistence behavior. On another project, identify what must not change during a preview and assert that boundary in a test.

Relevant verification

  • tests/test_citizen_auth.py checks sign-up, session behavior, ownership, and access gates.
  • tests/test_media_workflows.py checks coordinates, image validation, private access, and team photo updates.
  • tests/test_team_workflow_api.py checks staff authentication and workflow updates.
  • Run from the repository root: python -m pytest -q.

Run locally with python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload.
